# Learnings — S012
- An illustrated edit is **not** the source-of-truth model: a raster can reinterpret materials/camera but cannot establish parcel coordinates, dimensions, Revit objects, structural adequacy or legal rights. Keep GIS/CAD/BIM and the untouched photo as evidence; QA against them, not against prompt plausibility. Claim bound by P01–P04/P17/P21 and S07/S09.
- Provider controls diverge: FLUX.2 has no separate negative-prompt field, while certain Stability edit/control endpoints expose one; Midjourney Image Prompts inspire, not reproduce; Veras' Geometry Override exists but older reviewer S09 saw departures. This is not an inter-provider benchmark. P07–P11/S09.
- Mapping licences require product and item specificity. Google Geo Guidelines' alteration/disclosure language coexists with Earth commercial-use limits; Map Tiles API analysis rules are service-specific. Esri static-map terms and item rights must not be conflated. P12–P16. A copyrighted map is not an automatic image-model input.
- Image-evaluation claims are weaker than they look: P20 studies student text richness, P21 site-relational logic, and P22 a technical multiview task. None tests these prompts on the user's project. S14 forum developer's “client ready” view is interested, not a measured success rate.
- **Debts:** No user images or model, no platform-account test, no geospatial truth comparison, no local legal or code review. A current release gate pins a different v3.10.40 nine-path candidate delta; research can be proposed but must not be represented as a passing/apply-ready release.
- **Validation boundary:** the local validator was green for failure-class checks, but the complete 231-test suite was red in 3 `test_verify_tool_io` cases because the pinned candidate base object is missing/its allowed-path delta mismatches and the worktree is intentionally dirty. Tests were not edited or suppressed; this is an existing release-environment mismatch to surface to the Commander, not proof of a passing Patch.
